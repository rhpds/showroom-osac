Read through this page before starting Module 1. It covers timing, what you need to know coming in, and how to reach every part of your lab environment. Five minutes here will save you time during the hands-on exercises.

== Timing and Schedule

=== Full Workshop (90 minutes)

* *Module 1*: Exploring the Red Hat Cloud Extensions Platform (30 minutes)
* *Module 2*: Managing Tenants (30 minutes)
* *Module 3*: Catalog Items and Workloads (30 minutes)

Each module builds on the previous one, but they are structured so that a knowledgeable platform engineer can also pick up at Module 2 or Module 3 independently. No formal breaks are scheduled — pause between modules as needed.

=== Abbreviated Workshop (60 minutes)

* *Module 1*: Exploring the Red Hat Cloud Extensions Platform (20 minutes)
* *Module 2*: Managing Tenants (25 minutes)
* *Module 3*: Catalog Items and Workloads — core exercises only (15 minutes)

Skip the verification and troubleshooting steps in each module when running the abbreviated schedule.

== Prerequisites

=== Knowledge

You should be comfortable with:

* OpenShift concepts — projects, namespaces, operators, and the `oc` CLI
* Kubernetes resource types, including Custom Resource Definitions (CRDs)
* Reading and editing YAML
* Linux command-line usage at an intermediate level

You do not need prior experience with storage, Keycloak, Kafka, or Red Hat Cloud Extensions. Each component is introduced in context as you encounter it.

=== Software Requirements

All hands-on work runs inside the browser-based terminal Showroom provides. You do not need to install anything locally to complete the workshop.

If you prefer your own terminal, you need:

* *OpenShift CLI (`oc`)*: available at https://mirror.openshift.com/pub/openshift-v4/clients/ocp/latest/[mirror.openshift.com^]
* *osac CLI*: pre-installed in the lab environment (bastion host)
* *Web browser*: Chrome, Firefox, Safari, or Edge (current release)

== Environment Verification

Run these commands in the Terminal tab to confirm the lab is ready.

Confirm your OpenShift identity:

[source,bash,role="execute"]
----
oc whoami
----

Expected output: `{openshift_cluster_admin_username}`

Check the overall cluster version:

[source,bash,role="execute"]
----
oc version
----

Verify the Red Hat Cloud Extensions operator pod is running:

[source,bash,role="execute",subs=attributes]
----
oc get pods -n osac -l app.kubernetes.io/name=osac-operator
----

All pods should show `Running` or `Completed`. If any show `Pending`, wait 60 seconds and retry.

Check the full set of Red Hat Cloud Extensions pods:

[source,bash,role="execute",subs=attributes]
----
oc get pods -n osac
----

You should see pods for the Red Hat Cloud Extensions operator, fulfillment service, Keycloak, and Kafka. All should be `Running` or `Completed`.

Confirm the osac CLI is available and configured:

[source,bash,role="execute"]
----
osac --version
----

== Troubleshooting

=== Cannot Log In to the OpenShift Console

Confirm you are using the correct credentials:

* *Username*: `{openshift_cluster_admin_username}`
* *Password*: `{openshift_cluster_admin_password}`

Try an incognito or private browser window to rule out a cached session. If the login page does not load, verify the URL is exactly {openshift_console_url}^.

=== Red Hat Cloud Extensions UI Does Not Load

Check that the ingress route exists in the `osac` namespace:

[source,bash,role="execute",subs=attributes]
----
oc get route -n osac
----

If the route is missing, the Red Hat Cloud Extensions operator may still be initializing. Check pod status:

[source,bash,role="execute",subs=attributes]
----
oc get pods -n osac
----

Wait until all pods are `Running`, then refresh the Red Hat Cloud Extensions UI URL.

=== osac CLI Not Found

The `osac` binary is pre-installed on the bastion. If the command is not found, confirm you are in the bastion shell rather than your local terminal:

[source,bash,role="execute"]
----
echo $HOSTNAME
which osac
----

If `osac` is absent from the bastion, ask your instructor — the binary path may need to be added to `PATH`.
